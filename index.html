Final Project

A Linux-first workstation for acousmatic, aleatory, and automatic music.

Pieces are written in a Lisp dialect and run on a native C++ engine. The engine is agnostic about I/O: MIDI, OSC, web APIs, serial devices, and scripts can all feed it, and it can send to audio, visuals, MIDI, OSC, web APIs, and serial devices. A companion website lists live data APIs that pieces can use.

01

Problem

I'm on Linux, and while audio tooling there is improving, there are still gaps. REAPER runs natively, but Native Instruments, Spitfire Audio, and Max don't support Linux. They run only through Wine or yabridge, which none of those vendors support.

The open-source options each cover part of what I want. Pure Data and Max are visual languages, and patches get hard to work with past a certain size. SuperCollider handles synthesis and algorithmic composition, but on Linux the stable release has to be built from source or installed as a Flatpak, and its graphics stop at GUI widgets and 2D drawing. TidalCycles is built for live coding and runs on top of SuperCollider.

Three of the six assignments in this course focused on audio for this reason: I wanted to see what could be done in the browser, which is functionally a universal desktop platform. Those experiments hit performance and feature walls. Assignment 5 caps a piece at four reverbs, and a piece of about 300 lines produces audio artifacts when the browser has to compete with other processes for CPU time.

The final project moves this work to a native app. It's aimed at pieces that are written once and left to run, driven by rules, chance, and live data, with sound and visuals in the same script.

02

Features

Everything in a piece is a source, a sink, a modifier, or a pipe. Sources produce data: MIDI, OSC, web APIs, serial devices such as microcontrollers, and scripts that generate triggers or synthetic data. Sinks receive it: audio, visuals, MIDI, OSC, web APIs, and serial devices. Modifiers, such as instruments, effects, and mappers, take data in and change it. Pipes connect everything and carry audio, control, or event data, modeled on SuperCollider's buses.

Because sources and sinks are handled the same way, a MIDI controller can drive a web API, and a microcontroller can drive a reverb.

Instruments, effects, and scripts are written in code and reused across pieces. The language is a custom Lisp dialect with CLOS-style objects (defclass, defmethod, inheritance), and scripts compile to a validated IR. Visual layers take the same inputs as the sound.

The companion website is a directory of live data APIs. Each entry lists the endpoint, whether it needs a key, its fields and units, its refresh rate and rate limits, and a snippet to paste into a piece. Anyone can browse it. Signing in lets you save entries, and the app pulls your saved list with a personal token. The app fetches data from each API directly.

03

Users

Musicians on Linux, generative and installation artists, and people who use Max or SuperCollider.

I haven't done the interviews yet because of time constraints. Three written interviews are planned for November 4–9, early enough to shape the language spec.

04

Focus

Systems. Most of the work is architecture: a real-time audio engine that never allocates, locks, or touches files on the audio thread; an interpreter that compiles scripts to a validated IR, which is the contract between the language and the engine; and bindings for MIDI, OSC, web data, and serial devices, with mappers that run off the audio thread.

It's also what I want to learn: DSP and language design.

06

Stack

ToolRole
C++ and JUCENative, with no web runtime. JUCE covers ALSA and JACK audio, MIDI, OSC, the UI, an OpenGL context, and plugin export later on. Its AGPLv3 option fits an open-source, non-commercial project.
Lisp dialectS-expressions map almost directly onto the IR tree.
Catch2Tests for the interpreter, compiler, IR validation, and DSP, run through CTest.
ValgrindMemcheck on the test suite and offline renders, to catch leaks and bad memory access. Too slow for real-time runs.
CMakeBuild system. JUCE supports it directly.
PipeWireThe audio server on most Linux desktops. The ERR column in pw-top counts xruns for the performance test.
GitHub CLIgh for the repository and releases.
Doxygen, Sphinx, BreatheAPI reference from the C++ source, plus the user guide and language reference. Breathe pulls the Doxygen output into Sphinx.
VercelHosts the directory and this page.
SupabasePostgres for directory entries, saved entries, and hashed tokens, with row-level security. Free projects pause after a week without activity, so a daily scheduled query keeps it running.
ClerkSign-in for the directory.
Claude CodeBuilds the engine, tooling, and directory against the language spec.
Supabase MCPSchema, migrations, and access rules for the directory.
