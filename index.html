Final Project

A Linux-first workstation for acousmatic, aleatory and automatic music.

Pieces are written in a Lisp dialect. A script connects sources such as MIDI, OSC and live data to sinks such as audio, visuals and external programs, through instruments, effects and mappers. Any source can drive any sink. Scripts compile to an intermediate representation (IR) that a native C++ engine plays. A web directory lists live data APIs for use in pieces.

01

Problem

The author works on Linux. Linux audio tooling has gaps.

REAPER runs natively. Native Instruments, Spitfire Audio and Cycling '74 Max do not support Linux, and run only through unsupported compatibility layers such as Wine and yabridge. The open-source alternatives cover parts of the need:

  • Pure Data and Max are visual languages. Large patches are hard to read and maintain.
  • SuperCollider supports synthesis and algorithmic composition. Stable releases on Linux require a source build or the Flatpak build. Graphics are limited to GUI widgets and 2D vector drawing.
  • TidalCycles is a live coding environment for patterns. It depends on SuperCollider for synthesis.

Four of the six assignments in this course focused on audio, to test what the browser, a functionally universal desktop platform, can do.

Those experiments reached performance and feature limits imposed by the browser. Assignment 5 caps each piece at four reverbs. Pieces of about 300 lines produce audio artifacts when the browser competes with other processes for CPU time.

The final project is a native Linux application for that work. It targets pieces that are written once and then run on their own, driven by rules, chance and live data, with sound and visuals in the same script.

02

Features

A piece is a graph of four kinds of element:

  • Sources produce data: MIDI, OSC, web data, serial devices such as microcontrollers, and scripts that generate triggers or synthetic data.
  • Sinks receive data: audio, MIDI, OSC, web data such as another program's API, serial devices, and visuals.
  • Modifiers transform data: instruments, effects, and mappers.
  • Pipes connect elements and carry audio-rate, control-rate, or event data.

The engine treats every source and sink the same way. A MIDI controller can drive a web API, a serial sensor can drive a reverb, and a script can drive an external program over OSC.

  • Instruments, effects and scriptsDefined in code and reused across pieces.
  • Lisp dialectA custom Lisp dialect with CLOS-style objects: defclass, defmethod and inheritance. Scripts compile to a validated IR.
  • Visual outputVisual layers driven by the same sources as the sound.
  • Data directoryA public web directory of live data APIs. Each entry lists the endpoint, key requirement, fields and units, refresh rate, rate limits, and a binding snippet for a piece. Signed-in users save entries. The native app retrieves a user's saved entries with a personal token, and fetches each source directly.

03

Users

Musicians who work on Linux, generative and installation artists, and users of Max and SuperCollider.

Interviews: not completed, due to time constraints. Three written interviews are scheduled for November 4–9. Their findings inform the language specification.

04

Focus: Systems

The project's core is architecture:

  • A real-time audio engine. The audio thread performs no allocation, locking or file I/O.
  • A language interpreter that compiles scripts to a validated IR. The IR is the contract between the language and the engine.
  • Source and sink bindings for MIDI, OSC, web data and serial devices, with mappers that run outside the audio thread.

The focus matches the project's learning goals: DSP and language design.

06

Stack

ToolRole
C++ and JUCENative build with no web runtime. JUCE provides ALSA and JACK audio devices, MIDI, OSC, UI, an OpenGL context, and LV2 and VST3 plugin export. JUCE is available under AGPLv3, which fits an open-source, non-commercial project.
Lisp dialectS-expressions map directly onto the IR tree.
Catch2Unit and integration tests for the interpreter, compiler, IR validation and DSP, run through CTest. BSL-1.0 licence.
ValgrindMemcheck over the test suite and offline renders, for leaks and invalid memory access. Too slow for real-time runs.
CMakeBuild system, supported by JUCE.
PipeWire, pw-topAudio server on most Linux desktops. The ERR column of pw-top reports xruns for the performance criterion.
ghGitHub CLI for the repository and releases.
Doxygen, Sphinx, BreatheC++ API reference, user guide and language reference. Breathe imports Doxygen output into Sphinx.
VercelHosting for the data directory and this page.
SupabasePostgres for directory entries, saved entries and hashed tokens, with row-level security. Free projects pause after a week without database activity; a daily scheduled query keeps the project active.
ClerkSign-in for the directory.
Claude CodeImplementation of the engine, tooling and directory against the language specification.
Supabase MCPSchema, migrations and access rules for the directory.
